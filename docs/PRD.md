**一句话**：负向措辞的**静态答案是有的**——NVIDIA 已把 *explicit negative/boundary phrasing* 写进 **Discoverability** 维度（权重 0.25），并发表于论文 **arXiv:2608.20614**。

> 📌 **长度规则的更正（依 D-016）**：description 长度的**真实评分规则是「`>200` 字符扣 5 分」**；
> 论文中「50–150 preferred」**只是提示文案，不是评分规则**。我方 description 135–184 字符，**全部安全**。

**空白在运行时**：负向措辞对**运行时误触发率的边际收益，从未被量化**。

**而这一点，NVIDIA 自己已给出理由**——该论文证明**静态评分无法预测运行时行为**：

negative case 仅有**质性分类、无系数**。

**本项目补的就是这一格**：用四臂消融测出负向措辞在**运行时**的净收益。

## 1. 一句话定义

**产品是载体，方法是贡献。**

以「工业安全巡检」为**具体场景载体**（让方法不抽象、可演示），交付一套**可复现的量化方法**：
用四臂消融测出 Agent Skill `description` 中**负向措辞对运行时误触发率的边际收益**。

> 巡检 Agent 是这套方法的**演示载体**，不是本项目的贡献声明。
> 本项目**不主张**任何行业 know-how 优势，**不承诺**真实产线落地效果。

## 5. 创新点：三层分级路由（技术深度得分主力）

设计哲学对齐 NVIDIA **NeMo Switchyard**（规划类请求给前沿模型、高频执行给轻量模型），
但针对**视觉巡检**这一垂直场景做了专门化——Switchyard 本身是通用文本路由，不处理图像置信度。

| 层 | **实现状态** | 触发条件 | 载体 | 单帧成本 | 单帧延迟 |
|---|---|---|---|---|---|
| **Tier 0** | **[已实现]** | 逐帧人形定位与计数；**无人的帧直接短路** | YOLO11n（本地，`models/yolo11n.pt`） | 0 | ~10–13 ms* |
| **Tier 0.5** | **[已实现]** | 有人员时做着装颜色初筛 | 颜色-几何启发式（本地，零模型依赖） | 0 | ~10 ms* |
| **Tier 1** | **[已实现]** | 需确认 / 推翻 Tier 0.5 的初筛 | Qwen3-VL-2B（本地，`models/Qwen3-VL-2B-Instruct/`） | 0 | 13.9 s* |
| **Tier 2** | **[已实现·本次未授权]** | 多目标冲突 / 需长链推理 / 生成报告 | StepFun Step 5 API | ¥计价 | ~3–15 s |

> **实现状态以本表为准。** 本地三层（Tier 0 / 0.5 / 1）**已在 RTX 5060 Laptop 8 GB / Windows 上跑通**；
> 权重预置在 `models/`，**无需联网下载**（可离线运行）。
>
> `[*]` = **运行报告值，尚未落盘**（`docs/local_tier_metrics.json` 只记录逐层调用次数）。
> **对外引用请用逐层调用次数（Tier 0/0.5/1/2 = 3 / 2 / 2 / 0）——它是确定性的**；
> **墙钟时间会波动，不作为对外指标。**
>
> ⚠️ **Tier 2 本次未调用的原因是「未授权」**（`cloud_authorized=False`，被 `route.enforce_safety_boundary`
> 压回本地），**不是「按需判断后不需要」**——本次运行**未验证** Tier 2 的路由触发逻辑。
> 详见 `docs/DELIVERY.md` §3.3。

> **预算约束（已确认）**：StepFun Key 已有但预算有限，Tier 2 触发条件需收紧——
> 仅在「多目标冲突」或「生成最终报告」时调用，**单帧图像不送云端**。

**可量化产出**：
- **[已实现]** Skill 触发准确率与负向条件净收益 Δ2（四臂消融，本方案核心交付物）
- **[已实现]** **逐层调用次数**（`docs/local_tier_metrics.json`）—— **确定性指标，对外引用此表**
- **[已实现]** **分层收益的硬证据**：同流程三张照片中，有一张因 **Tier 0 判定无人而直接短路**，
  **未进入 Tier 0.5、未调用 Tier 1 的视觉模型**——省下的不是时间，是**根本不跑**
- **[待补落盘]** 逐层延迟与显存占用 —— 各层延迟为运行报告值；**墙钟时间会波动，不作为指标**

### 本地通路：**已实现**

本地推理通路（Tier 0 / 0.5 / 1，对应 D-009 阶段 B1/B2）**已在本机跑通**：

- **现状** → **本地模型已加载并推理**：`models/` 预置权重（YOLO11n + Qwen3-VL-2B），
  `.venv` 含 `torch 2.11.0+cu128` / `transformers 5.17.0` / `ultralytics 8.4.159`
- **可对外报告** → 逐层调用次数、分层短路带来的节省（见上文「可量化产出」）
- **仍不可报告** → **「本地兜底率」**：`BudgetState` 没有总任务数与本地解决数，
  `local_fallback_rate` 输出 `None`，**不臆造数值**（详见 `docs/DELIVERY.md` §8.2）

> 原「**本地兜底率 > 90%**」曾作为核心对外指标，现**不再作为承诺**。
> 原因**不是它未实现**，而是**当前口径算不出来**——需先补齐 `tasks_total` 与 `tasks_resolved_locally` 的计数。
>
> ✅ **依赖清单已补齐**：`transformers` / `ultralytics` 已列入 `requirements.txt`；
> `torch` / `torchvision` 因需 **cu128 专用索引**，改为**两步安装**（见 `docs/DELIVERY.md` §5.2）。
> `[已实测]` 八个固定版本对官方 PyPI **解析成功、无冲突**；cu128 索引存在 cp312 win_amd64 wheel。

**本地通路的第二个用途（低门槛，待决策）**：
A5 四臂消融是**纯文本路由实验、不读图**，因此在本地跑的是**小 LLM 而非 VLM**，
硬件门槛远低于原先设想的「本地视觉」。

若负向措辞的**运行时收益跨模型一致**，结论就从「某云模型上的一次观察」升级为
「**跨模型稳健的效应**」——而这正是 NVIDIA 论文承认缺失的那类**运行时证据**。

> 这一节直接对应评分表「智能体和模型优化技术深度 25%」。

## 6. Agent Skill 设计（本赛命题核心）

按 [agentskills.io](https://agentskills.io) 规范，对齐 NVIDIA 官方技能包结构。
实际产物为 **1 个编排层 + 3 个窄触发子技能**（D-011 两轮验证通过，共 33 文件）：

```
skills/
├── inspection-orchestrator/   # 编排：决定调谁、定层级
├── safety-hazard-detection/   # 窄触发：图像 → 隐患标签
├── gauge-reading/             # 窄触发：表盘 → 一个数
├── inspection-report/         # 窄触发：结论 → 报告
│        每个技能 = SKILL.md + scripts/ + references/ + evals/
└── evals/                     # 顶层四臂消融套件（A/B/C/D，40 条用例）
```

**拆分判据**：不是「功能多少」，而是**触发条件能否用一句话说清且互不重叠**——四者两两不相交。

**判定项**（v2 范围，可裁剪）：未戴防尘帽、未穿防静电服、人员违规闯入、消防通道堵塞、设备渗漏、仪表读数异常。
（v1 曾为「未戴安全帽 / 未穿反光衣」，已按**电子厂洁净车间**真实场景对齐；旧项保留为 v1 遗留，见 `docs/agents/experiment-version-note.md`。）

> ⚠️ **上列「判定项」是 taxonomy 范围，不等于本版本可检测。**
> **本地三层流水线目前不可检测**：通道堵塞 / 设备渗漏 / 明火烟雾 / 未戴手套口罩 / **精确人数**。
> **表上一个 ❌，就是演示里一句不能说的话**——完整清单与原因见 `docs/DELIVERY.md` §8.1。
