## 1. 五类「绿 ≠ 看起来的意思」

**它们的共同点：不是断言写错了，是断言的主语不是风险所在的那个东西。**
所以**全绿** —— 因为断言本身是真的。

| # | 类别 | 形态 | 当日实例 | 堵法 |
|---|---|---|---|---|
| 1 | **假绿** | 断言过了，但**没执行到被测行为** | `--date` 与 `captured_at` 取值**恒相等** ⇒ 优先级那条逻辑从没被执行过；变异体缩进写错导致套件提前 bail、某用例根本没跑 | **变异自检** + **先证明分支被走到** |
| 2 | **绿而不完整** | 整套过了，但其中**一部分从没跑过** | auto 模式遇 SKIP，**退出码仍为 0** ⇒ 只看退出码的门把「集成半场压根没跑」判成通过 | **退出码 0/1/2** + **不许 SKIP 计入通过** |
| 3 | **覆盖表声称有覆盖** | 一句话声称某物被保护，**没有任何东西在执行它** | 11/11 全绿但**从没碰过全局导出**；§E.1 写在覆盖表里**却无断言**；14 条全绿但**从没加载过「分发的原样」** | **让断言加载「要交付的那个东西」** |
| 4 | **工具替未证结论背书** | 工具把没证过的结论**印成事实** | D0 把「文件名是 `inbox.json`」当成「**是产出物**」并这么印 | **只报契约判据可查的事实** |
| 5 | **断言已撤回的主张** | 套件在**断言一条已被证伪的话** | T1b 断言 §C.6 那个后来被撤回的判别式；SKIP 文案写「契约未规定查询入口」，而 v1.13 之后已不成立 | **撤回时必须同步重塑断言**，并让解析器拒绝把已撤回文字当期望源 |

> **第 5 类最阴**：**「断言一条已被撤回的主张」比没有断言更坏** —— 因为没人会再去看它。

## 2. 四条纪律

### ① 证据必须能证伪结论
写结论前先问：**「如果这条结论是错的，我这份证据会是什么样？」** 答不上来 ⇒ 证据还没到。
**「零命中」这个结论本身也需要证据** —— 当日脱敏复检每次都附**正对照**（grep 一个必然存在的串，确认搜索机制在工作），
因为**「0 命中」与「grep 坏了」长得一模一样**。

### ② 先证明「被执行了」，再谈绿不绿
- **分支真的被走到**：`viewready` 触发了几次？去重分支 log 了几次？
- **参数非退化**：两个值恒相等 ⇒ 那条分支从没跑过（当日实例：日期回落链）
- **断言先经变异验证有效力**：**测不到变异的断言没有效力**
- **变异必须打在真实分支上**：当日 D6 第一版拿 `desc` 当变异，而 `desc` 可由产物反推 ⇒ **那条变异永远抓不到**
- 🔴 **变异必须证明「信号来自这条护栏」**（当日 R2-S 的 `selfcheck_enums.py`，本轮最强的一条方法）
  - **D0** 基线：无信号
  - **D1** 变异数据：**必须报**
  - **D2** 放宽被验的常量：**必须变哑**
  > **没有 D2，D1 证明不了什么** —— 信号可能来自别处代码碰巧挡下，而不是这条护栏。
  > **判据升级：不只问「断言会不会红」，还要问「它是不是因为对的原因红的」。**
- 🔴 **验证要用「要交付的那个东西」的解析器，不要用自己写的**（当日 R2-B 的 T12/T13，
  它刻意调用 `query_core` 的真解析器而非自写正则）
  > **「按我的理解解析成功」证明不了「消费者读得懂」。**
  > 这与「14 条断言从没加载过分发的原样」是同一形状：**测的解析器 ≠ 消费方的解析器**。
- 🔴 **检查工具不得把自己的检查对象消掉**（当日出现三次，同一族）
  | 实例 | 它怎么消掉要查的东西 |
  |---|---|
  | 自检还原产物时用 `write_bytes` | **刷 mtime** ⇒ 每跑一次就毁掉一次 `produced_at ↔ mtime` 的证据 |
  | 换行断言用**文本模式**读 | `\r\n` 被归一成 `\n` ⇒ **正好抹掉要抓的 `\r`** |
  | 自检写回时按文本模式 | **把 CRLF 写成 LF** ⇒ 断言永远看不到它要看的形态 |
  > **判据：断言读文件时先问「我用的这条通道，会不会把它要检查的特征转换掉？」**
  > **换行、编码、时间戳、大小写——凡是"读取时会被归一"的属性，都必须按字节/按原始形态读。**
- 🔴 **跑批量断言前，先证明「用例数与输入行数一致」**（当日探针实例）
  > 探针脚本里 `claude` **吃掉了 stdin**，把 `while read` 的剩余行吞了 ⇒ **只跑了 13/16，而输出看起来是完整的**。
  > **差点把「13/13 正确」当成完整覆盖报出去。**
  > **判据：批量测试的覆盖率本身要有一条断言（每组的落行数 == 用例数），否则"全绿"可能只是"跑得少"。**

### ③ 让结论与环境无关，而不是控制环境
当日冻结哈希三轮对不上，根因是 CRLF/LF。**修好 autocrlf 是补丁**；
最终解法是 **canonical 哈希**（按 LF 归一后计算）——
**在 CRLF↔LF 下不变** ⇒ **循环不是被堵住的，是在被扰动的那一维上成了不变量。**
> **判据：能「让结论与环境无关」时，不要选「把环境修好」。**

### ④ 一条在别人机器上必然报警的门，与永远红的门同类
都会被训练成**「看见红也不当回事」**。
⇒ 门必须在**验收方**的机器上也有意义；否则降级为**信息性报告**。

## 4. 一条可复现的环境坑（Windows Git Bash）

```bash
printf 'name = user\n' | sed 's/r$//'
#   →  name = use          ← 静默删掉了行尾的 r
```

**反斜杠一旦被吞，`\r` 退化成 `r`，命令仍然"成功"、什么都不报。**
⇒ **不要用 shell 里的 `\r` 做换行归一**；改用 Python（显式读写、`newline='\n'`），那步是确定的。

（同类：本仓 `CLAUDE.md` 记的 `\\` 被吞问题。**同一个坑，换了一副面孔。**）
