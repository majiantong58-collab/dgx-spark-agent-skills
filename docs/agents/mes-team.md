## 1. 本阶段的最大风险（它决定了团队为什么长这样）

**跨边界契约漂移。**

skill 侧产出 JSON、原型侧读取渲染 —— 两个**工作区**（invda / MES）、两个执行者、一份**隐式**契约。失效方式是**静默的**：字段名不一致 → 什么都没渲染 → 界面上看起来"没发生任何事"。

> 这正撞在本项目自己的教训上（`decision-log.md` D-027 教训 2）：
> 「只改管线而不改界面，则**故障在界面上仍然长得像「没事」** —— 而界面才是演示与评审看到的那一层。」

⇒ 两个**结构性**应对（不靠纪律，靠机制）：

1. **契约冻结 + 版本号**：JSON 自带 `schema_version`；原型 loader 遇到不认识的版本**显式报错**（可见横幅），**禁止静默跳过**。契约文件 = `docs/agents/mes-bridge-contract.md`（M0 落盘）。
2. **R5 契约官**（见 §2.2）。

### 2.2 新增常设：R5 契约官

| 代号 | 职责 | 建议类型 | 档 | 关键约束 |

| **R5 契约官** | 拥有 `mes-bridge-contract.md`；跑契约测试；两侧对齐 | `general-purpose` | 中 | **只改契约与测试，不改两侧实现** |

**为什么值得单列**（base 原则是"常设角色保持最小"）：

**没有人拥有"两侧说的是不是同一件事"**，而该失效又是静默的。

**撤编条件**：M3 过闸且契约测试进入常规回归后，R5 转为按需（不保留上下文）。

## 4. Loop 设计（三层环 + 一个对抗环）

| 环 | 范围 | 机制 | 出处 |
|---|---|---|---|
| **内环** | 单任务 | 执行 → 验证 → 过/回炉/降级（回炉 ≤2） | `team.md` §4.1 |
| **外环** | 每道闸 | R3 **全量独立复现**才可过闸；不过则回炉，超限降级 | `team.md` §4.2 |
| **守护环** | 长线程 | R4 按触发条件巡检；**总监理在每个闸口出一份书面裁决** | `team.md` §5 |
| **对抗环** | M3 后 | 红队专攻负向用例（§2.3） | 本文件 |

**书面裁决格式**（总监理落 `decision-log.md`，D-0xx）：

```
闸门：M1
裁决：PASS | REWORK | DOWNGRADE
依据：R3 复现命令 + 期望输出 vs 实际输出（一行）
回炉单：<若有，列出>
过期清单：<本次改动使哪些文档的现状断言过期 —— 先 grep 特征措辞，再列>
```

> 「过期清单」一节取自 `fact-single-source.md` §6：**先 grep，再列**。写不出就写 `none`，
> 但**必须先搜过**——该规则明说，漏掉的不是"懒得写"，是"没想到"。

### A.4 复核补充（**M0 前不存在于本附录，由 R1-A 独立发现**）

| # | 补充事实 | 为什么重要 |
|---|---|---|
| 1 | **部门枚举有两处**：`index.html:2230`（筛选下拉）+ **`:9305`（登记抽屉 `data-exc-dept`）** | 若要加「安全部」**须同步改两处**，漏改 9305 会导致抽屉选不到 |
| 2 | **`data-total` 运行期被重算**：`refreshExcTotals`(`:9209`)；不可变基数存 `tbody[data-base]` | 计数**不得自行计算**，必须走既有机制，否则漂移 |
| 3 | **`data-dcm-mt-row` 是无值属性** | 与 `data-mt-st="…"` 等不同，拼接时不能写成 `data-dcm-mt-row=""` 之外的形式 |

| 6 | **原型无任何外部数据加载机制**（A11 确认=不存在） | 桥是从零建，不存在重复造；唯一持久化是 localStorage 且只存 UI 偏好 |
