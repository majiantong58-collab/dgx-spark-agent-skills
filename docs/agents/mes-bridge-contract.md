| 项 | 宿主必须提供 | 锚点 |
|---|---|---|
| 行标识 | `<tr data-dcm-eq-row …>`（**无值属性**） | `index.html:5520` |
| 状态枚举 | 行属性 `data-st` ∈ `在用` / `维修中` / `停用` / `已报废` | `index.html:5520-5525` |
| 单元格 | **前 6 列依次**：设备编号 · 名称·型号 · 所属工位 · 车间·产线 · 接口类型 · 状态 | `index.html:5505-5516` |

> **刻意不要求** `data-ws` / `data-line` —— 参考实现有，但与单元格内容重复，**最小宿主可省**。
> 消费者只认 `data-dcm-eq-row` + `data-st` + 前 6 列序。

> 📌 **为什么不对称**（v1.14 说明 —— 曾有一版想统一成「都走 DOM 行」）
> **工单的静态 DOM 是空的**：`<tbody id="woTbody"></tbody>`（`index.html:3418`），行由 JS 渲染；
> 而**设备台账的行就写在 HTML 里**。两种数据的**自然形态本就不同**。
>
> **统一会让主宿主不合规**：契约要能容纳参考原型（它是主宿主）。若强制工单走 DOM 行，
> 参考原型就必须改渲染路径——**为了契约的整齐去改一份已验证的实现，是本末倒置。**
>
> ⇒ **契约如实描述「数据在宿主里以什么形态存在」，而不是规定它该以什么形态存在。**

## B · 注入契约（**复用原型原生路径，不自写渲染器**）

### B.1 唯一允许的注入方式

```js
addExcRow(sec, o)      // :9227-9233
```

> ⚠️ **前置条件（v1.2 新增）**：`addExcRow` 位于 qm.js **私有 IIFE**（`:8678–10086`）内，
> 全文件唯一全局导出是 `MESHOST`(`:7991`)，**不含它** ⇒ **直调不可达**。
>
> **授权解法**（用户批准，2026-09-28）：在既有 IIFE 内加**且仅加**一行
> ```js
> MESHOST.exc = { addExcRow: addExcRow };
> ```
> **代价已接受**：本行属**改既有代码**（虽为纯增），是本契约唯一一处对交付区产物的既有区域改动。
> 验收要求：diff 须证明既有 IIFE 区域内 **removed 0 / modified 0，仅 +1 行**。
>
> 📌 **命名约定（v1.12 新增）**：`MESHOST` 是**本仓库约定的宿主命名空间名**。
> **契约的实质要求是「宿主把 `addExcRow` 暴露为一个全局」** —— 具体命名空间名**由宿主自定**，
> 外部宿主可用其自身命名空间，**不影响契约效力**。
> （原名为一个可还原出第三方名称的缩写，**为公开仓库脱敏而改**；宿主实现随之统一。）
>
> **替代路径（未采纳）**：驱动原型「登记异常」入口（`[data-exc-new]`→抽屉→`[data-dv-save]`）
> 可在零改动下完成插入与计数，但会**写死 `no`/`rel`/`date`/`finder` 四字段**（R2-B 实测），
> 使 §C.1/§C.2 失效 ⇒ 不采纳。

它一次性完成四件事，**全部一致性免费拿到**：

| 步 | 动作 | 职责 | 锚点 |
|---|---|---|---|
| 1 | `insertAdjacentHTML('afterbegin', excRowHtml(o))` | 插入行 | `:9229` |
| 2 | `tbody[data-created]` **+1** | 新建计数器 | `:9230` |
| 3 | `refreshExcStats(tb)` | **页面状态统计**（如闭环步进条各态条数） | `:9231` |
| 4 | `refreshExcTotals(tb)` | 🔴 **计数真源**：`data-total`（公式见下方注）＋分页 `.pagination span b` | `:9232` |

> ⚠️ **两个刷新函数的分工原契约只列了调用、没写职责**（v1.10 补，R2-B 实现宿主页时提出）。
> **判据**：`refreshExcTotals` 是**计数真源**那条链；`refreshExcStats` 管页面上的**状态统计**。
> 宿主页实现时两者都须非空——**空实现会让某一半静默不更新**。

> 🔴 **禁止手搓计数。** `data-total` 的公式是 `base + data-created`（`:9221`，**不是行数**），
> base 惰性初始化为 `96`（`:9218-9219`）。它是唯一真源，不 bump 则**页头「共 N 条」与分页同时错**（`:9224-9225` / `:8757-8762`）。

### B.2 `excRowHtml(o)` 入参（`:9176-9184`）

| 字段 | 说明 | 约束 |
|---|---|---|
| `no` | 异常单号 | 写入 `data-no` |
| `rel` | 关联检验单 | 写入 `data-rel`。**只参与文案，不参与部门判定**（见 B.3） |
| `dept` | 责任部门 | 必须∈ A.1 部门枚举 |
| `desc` | 异常现象 | **见 §D 安全约束** |
| `iso` | 是否隔离 | **JSON 侧为布尔；loader 负映射责任**（见下） |

> 🔴 **`iso` 的映射责任在 loader，不在 skill**（v1.5 裁决，R2-B 实测上报）
> `excRowHtml`(`:9182`) **仅在取值 `=== '未隔离'` 时才显示「未隔离」**，
> ⇒ **直接传布尔 `false` 会误显示为「已隔离」**（静默显示错误）。
> **裁决**：JSON 保留 `iso: boolean`（**语义层**，干净）；
> **loader 负责映射** `true → 已隔离` / `false → 未隔离`（**呈现层**）。
> 理由：呈现映射属于边界，不该让 skill 产出原型专用的显示字符串。
| `finder` | 发现人 | — |
| `time` / `date` | 发现时间 / 日期 | 写入 `data-date` |

> ⚠️ `excRowHtml` **把 `data-status` 写死为 `found`**（`:9178`），badge 也随之写死「待处理」。
> 若需其他状态，须在注入后由 `setExcRow` 重设，**不得改 `excRowHtml` 本身**。

### B.3 部门判定不由 `data-rel` 决定（**前提更正**）

`excRelMeta(rel, src)`(`:9186-9195`) 按 **`src`** 索引，**不是 rel 前缀**：

```
iqc → 供应商 ｜ fai / pat / oqc / scan → 生产部 ｜ 未知 src → 回退 生产部（不报错）
```

⇒ **`data-rel` 的格式不承载部门语义**。本契约**不规定** `rel` 的前缀规则。

### B.4 🔴 幂等要求（**v1.4 新增 —— 原契约漏掉**）

`viewready` **每次切回该视图都会重触发**。若 loader 每次都注入，则**切走再切回会重复注入**，
`data-total` 会 97 → 98 → 99……**且界面上看起来完全正常**（这正是本阶段最怕的静默失效形态）。

**要求**：loader 必须保证——**同一 `no` 在一次页面会话内最多注入一次**。

| 情形 | 行为 |
|---|---|
| 首次 `viewready` | 逐条注入 `records[]` 全部 `quality-exception` |
| 再次 `viewready`（切走又切回） | **跳过已注入的 `no`**，不重复注入 |
| 页面刷新 | 会话重置，**重新注入**（页面 DOM 亦已重置，非重复） |

**验收**：切走该视图再切回 **≥2 次**，`data-total` 保持 `97` 不变。

### B.5 可选：高亮

`highlightExcRow(sec, no)`(`:9227` 调用链 `:9336`) —— 演示时用于把注意力引到新行。非必需。

{
  "schema_version": "1",
  "produced_by": "mes-inspection-intake",
  "produced_at": "2026-09-28T14:32:00+08:00",
  "records": [
    {
      "kind": "quality-exception",
      "no": "QA-20260928-101",
      "rel": "XJ20260928001",
      "dept": "生产部",
      "desc": "洁净间 3 号工位 1 名人员未穿防静电服",
      "iso": false,
      "finder": "巡检 Agent",
      "time": "14:32",
      "date": "2026-09-28",
      "provenance": {
        "source_skill": "safety-hazard-detection",
        "confidence": 0.86,
        "evidence_ref": "mes-data/evidence/20260928-1432-01.jpg",
        "disclaimer": "本报告由 AI 辅助生成，结论基于图像证据自动判定，需经人工复核确认。本报告不作为处罚、停机或联锁动作的唯一依据。"
      }

```

**约定**：
- `records[]` 中**只有 `kind == "quality-exception"` 的项**进 `qm-quality-exception`；其余 `kind` 本版**忽略**（见 §E.2）。
- `provenance.disclaimer` 措辞**逐字取自** `skills/inspection-report/references/output-schema.md` §4（**单一措辞来源**，不得改写）。
  ⚠️ **v1.1 更正**：v1 曾误指 `inspection-orchestrator/references/`，该目录内**查无此措辞**（R2-S 2026-09-28 实证）。
  ⚠️ **v1.3 更正**：本节示例此前用**短版**措辞，与 §4 的**长版**不符（R5 契约测试 T9b 检出）。
  **裁决：以 §4 长版为准，全链统一。**

  > **为什么选长版而非把票据的措辞另立一源**（本条为**团队自定**判断）：
  > ① **单一来源优先**——另立一源等于多一个需要同步的东西，正是本契约要防的漂移；
  > ② **内容更完整**——长版显式含「AI 辅助生成 + 需人工复核」，恰是合规敏感场景该说的；
  > ③ 已知**代价**：长版主语是「本报告」，用在**单据**上略有错位。**记录为已知小瑕，不为它开第二源。**
- 字段名**一律小写连字符/下划线**，与 A.1 的行属性同名可对齐者优先对齐。

### C.1 `no` —— **必须由 skill 自生成**（不得复用原型函数）

🔴 原型 `nextExcNo()`(`:9168-9175`) **把日期段写死为 `20260813`**，只扫当前页 tbody 取 max+1
⇒ **复用它会生成错误日期**。

| 约束 | 值 |
|---|---|
| 格式 | `QA-YYYYMMDD-NNN`（3 位序，按日重置） |
| 日期来源 | 优先级：**`--date` 参数 > 发现记录的 `captured_at` > 系统当天** |
| **序号下限** | **`100`** —— 取 `max(100, mes-data/ 既有产出 max+1)` |
| 演示一致性 | M1 fixture **传原型世界日期**，使新单与库内 08-xx 行同时段可比 |

> 🔴 **为什么序号从 100 起**（v1.1 更正，原有自相矛盾）
> 原型库内 `QA-20260813-001/002/003` **已占用 0xx 序列**，而 M1 fixture 又要求用原型世界日期
> ⇒ **日期段必然重叠，从 001 起必撞号**。从 **100** 起是**构造上避免碰撞**，不依赖扫描时机。
> （R2-S 2026-09-28 实测占用并上报；原 v1 的「max+1」与「用原型世界日期」两条要求互相矛盾。）
>
> ⚠️ **v1.4 补充：日期回落链**（R2-S 实现 + 上报，裁决采纳）
> 原 v1「无 `--date` 用系统当天」**语义有误**：单据日期应是**巡检发生时刻**，不是脚本运行时刻。
> 现行优先级：**`--date` > 发现记录的 `captured_at` > 系统当天**。
> **已知测试盲区**：R5 测试恒传 `--date` ⇒ 该回落分支**测不到**（R2-S 自行指出）。已要求 R5 补用例。

### C.2 `rel` —— 写 `XJ<YYYYMMDD><NNN>`，**且该记录由 skill 一并产出**

- 沿用原型既有 `XJ` 格式（IPQC 制程巡检记录，`:3198`；无连字符，与 `IQC-` 系列不同）。
- 🔴 **该 `XJ` 巡检记录必须由本 skill 同时落到 `mes-data/`**——
  即 `rel` 指向的是**我们自己产出的记录**，不是凭空的号。
- 依据：`decision-log.md` **D-030** 裁决 6。

### C.3 `dept` —— **映射由我们定义，必须标 `[团队自定]`**

🔴 **MES 无明文部门判定规则**（`D-030` 事实 2），且 **MES 无「现场安全巡检」业务对象**
（事实 1：`防静电`/`堵塞`/`渗漏` 计数全 0；`FR-QM-006` 巡检范围明文**不含人员/PPE/通道**）。

| 巡检发现 | 落 `dept` | **当前可触发？** |
|---|---|---|
| 人员违规（PPE / 闯入） | `生产部` | ✅ **是** —— 唯一有实测能力的路径 |
| 通道堵塞 | `生产部` | ❌ **否** —— `SUBMISSION-CHECKLIST.md` §六：**当前无法检测** |
| 设备渗漏 | `设备部` | ❌ **否** —— 同上 |
| 仪表读数异常 | `设备部` | ❌ **否** —— 同上；且**未验证**（测试素材中无可用表盘） |

> 🔴 **v1.7 新增约束（2026-09-28，读 `SUBMISSION-CHECKLIST.md` §六 后补）**
>
> **上表后三行是「前瞻性规则」，不是当前能力。** 上游 `gauge-reading` 与
> `safety-hazard-detection` 对这三类**当前产不出结论**（见 `SUBMISSION-CHECKLIST.md` §六「不得宣称」表）。
>
> ⇒ **演示、文案、测试夹具一律只可使用「人员违规」这一类发现。**
> ⇒ 上表**不得**被读作「我们支持四类巡检落单」。**描述本 skill 能力时，只能说它覆盖人员违规。**
>
> **本条的教训（与契约前 6 处自相矛盾同源）**：我写规则时**没有回头核上游能力的边界**。
> 规则本身不假，但它**描述了不存在的输入**——这与 D-018「从未为真」同形：
> **不是漂移，是一开始就没有对应物。**

⚠️ **本表是团队自定，不出自 MES/SRS 任何材料**，引用处必须带此标注。
⚠️ `设备部` 在库内**零实例**⇒ 我们的单据将是**首个**。

**映射不中时：拒绝猜测**（v1.4 采纳 R2-S 实现）
若发现不落在上表任一行，**不得默认归入某部门**，须**停止并提示用 `--dept` 显式指定**。

> 此出口是契约未预先规定、由实现补齐的，**现补入契约**。

### C.7 `kind` ↔ `data-view` 映射（**v1.10 新增 —— 实现陷阱**）

🔴 **两个标识差一个 `qm-` 前缀，混用会使注入静默为 0 条**（R2-B 2026-09-28 实踩）：

| 用在哪 | 值 |
|---|---|
| JSON `records[].kind`（§C） | `"quality-exception"` —— **无 `qm-`** |
| DOM `section[data-view]`（§A.1） | `"qm-quality-exception"` —— **有 `qm-`** |

**loader 必须做这个映射**，且**映射不中时应可见地报错**（§F），不得静默跳过。

### C.6 产物来源可验证性（**v1.10 更正 —— v1.9 的说法被 R3 证伪为高估**）

> **问题**：手工写的文件**也能通过 schema 校验**。
> 所以「schema 合规」**证明不了**「它由流水线产出」——而后者才是本作品的主张。

#### ❌ v1.9 曾如此表述（**已更正，保留原文以备对照**）
> 判别式 `produced_at ↔ mtime` 一致性 —— 脚本产出 Δ≤1s / 手写件 Δ=46 天

#### 🔴 R3 的证伪（2026-09-28）
> **任何新写文件的 Δ 都 ≈ 0**。它只能查「**倒填时间的老件**」，**不能查「手写」**。

⇒ **这条判别式的作用域比 v1.9 声称的窄。** 手写者只要当场写文件，Δ 同样是 0。

#### ✅ 真正的来源证明：**复现**

**方法**：用**同一 fixture** 重跑 `commit.py`，其产物应与交付区文件**逐字节相同**（**仅 `produced_at` 不同**）。

**实测**（R3，2026-09-28）：交付区两文件与重跑输出 **830B / 475B 逐字节相同**，
连 **CRLF 计数 24 / 17** 亦一致 ⇒ **手写无法伪造这一点**。

| 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|
| schema 合规 | 字段对 | 谁写的 |
| `produced_at ↔ mtime`（Δ≈0） | **不是倒填时间的老件** | 不是手写 |
| **复现（逐字节相同）** | **由该脚本在该输入下产出** | —（本轮唯一有效的手段） |

> 🔴 **重跑操作须知**：`commit.py` 是**追加**语义（§C.4 明写「追加，不去重」）。
> **重跑前必须清空 `mes-data/`，否则两条累积 → `data-total` = 98，破 §B.4 的 97。**
> （R2-B 反证实测：带旧件重跑得 `records=2`；官方 harness `T6a` 亦现 101/102/103 三条，独立佐证同一语义。）

### C.5 `iso` —— 真实语义与默认值（**v1.6 新增，R2-S 实测**）

🔴 **`iso` 不是「是否涉及物料」，而是「是否实际执行了物料隔离」。**

**决定性证据**：两条**同为物料超差**的种子行取**相反**值 ——
`:2256` 电机线圈电阻超差 = **未隔离**（`badge-neutral`）；
`:2260` 绕线 PIN 伸出长度超差 = **已隔离**（`badge-quarantine`）。
若语义是「涉及物料即隔离」，这两条**不可能取反** ⇒ 它是**登记时的处置决定**，非发现类型的属性。

辅证锚点：列名「隔离标识」`:2251` ＋ 页面口径「生成隔离标识禁止流转」`:2203`
＋ 抽屉字段名「隔离标识（数量 / 区域）」`:9308`（取值形如 `已隔离 · 2,400 · QC 隔离区`）。

| 项 | 值 |
|---|---|
| **默认值** | **`false`** —— 现场四类发现（人员违规 / 通道堵塞 / 设备渗漏 / 仪表异常）**均不扣留物料** |
| `true` 条件 | 仅当明确涉及在制产品/物料批次**且已执行隔离** |
| **类型分流** | **不做**。上游 finding 契约**无「已执行隔离」信号源** ⇒ 分流的判据不存在，**硬做即编规则** |

> ⚠️ **本条为 `[团队自定]`**：MES/SRS **没有任何**关于「巡检发现该不该隔离」的规定。
>
> ⚠️ **`false` 必须配合 loader 的负映射才生效**（见 §B.2）：
> `excRowHtml`(`:9182`) 判的是字符串 `=== '未隔离'` ⇒ **直传布尔 `false` 会被静默显示成「已隔离」**。
> R2-S 改 `false` + R2-B 实现负映射(`:18574`) 两者**互为前提**——缺任一，该分支都是死的。
>
> ⚠️ **原型行为须知（非我方输出）**：`setExcRow`(`:9161`) 在任何状态推进时会改写该列
> （`closed`→「已解除」，其余→「已隔离」）⇒ **「未隔离」只在行保持 `found` 时可见**。

### C.4 `xj-records.json` —— 巡检记录副产物（**v1.1 新增**）

§C.2 要求 `rel` 指向的 XJ 记录**由本 skill 一并产出**，故落 `mes-data/xj-records.json`。

| 约定 | 值 |
|---|---|
| 结构 | 与 `inbox.json` 同构：`{schema_version, produced_by, produced_at, records[]}` |
| 记录字段 | `no`（`XJ<YYYYMMDD><NNN>`）/ `date` / `time` / `obj`（巡检对象）/ `finding`（发现摘要）/ `source_skill` / `confidence` / **`related_exception`**（对应异常单 `no`，供 XJ→单据反向追溯） |
| 去重 | **追加，不去重**。重复提交产生新记录（`no` 由序号机制保证唯一） |
| 消费方 | 本版**无自动消费方**（原型不读它）；它是 `rel` 的**指涉对象**，供人工/审计追溯 |

> **为什么不去重**：去重需要「同一次发现」的判定口径，而该口径未定义（属 `[团队自定]` 待定）。
> 递归原则：**未定义的口径不发明**——留白并记录，好过自造后再改。

## D · 安全约束（**必须实现**）

> 🔴 **`esc()`(`:8684`) 只转义 `& < >`，不转义引号。**
> 而 `no`/`rel`/`dept`/`date` 直接拼进 HTML 属性（`:9178`）。
> ⇒ **值中含 `"` 可逃逸出属性**，构成注入口。

**两侧都要堵（纵深防御）**：

| 侧 | 要求 |
|---|---|
| skill 侧 | 生成的字符串**不得含 `"` 或 `'`**；含则替换为全角引号或剔除，并在 stdout 记录一次替换 |
| loader 侧 | 进 DOM 前**统一做引号剔除**（`esc` 不足以防属性逃逸，loader 自行兜底） |

**另一条既有约束**（沿用 `ui/server.py:248`）：错误信息**必须抹掉本机绝对路径**。

## E · 已知雷区（R2-B 必读）

### E.1 「查询」会吞掉注入行（`bindList.query()` `:8787-8791`）

```
var orig = tbody.innerHTML → 插 skeleton → 600ms 后 tbody.innerHTML = orig
```

⇒ **在 600ms 窗口内注入的行会被整体覆盖抹掉**。
**缓解**：注入与「查询」不得紧邻触发；loader 注入应发生在 `viewready` 且**不与查询动作同帧**。

> 📌 **查询入口约定（v1.13 新增 —— R5 报的契约缺口）**
> 本节原先只写了「危险」与「不得同帧」，**却没说查询入口长什么样** ⇒
> loader **无法按契约可移植地判定「查询在途」**（原型用 `[data-q]`、宿主页用 `[data-exc-query]`，**两者都合原契约**）。
>
> **约定**：宿主须把「查询」触发元素标记为 **`[data-q]`**（本仓库约定名）；
> 与 §B.1 的命名空间同理，**契约的实质要求是「宿主提供可识别的查询入口」**，
> 外部宿主可用自身属性，但**须在其宿主说明中声明**，否则 loader 只能退回多路探测 + 记「不适用」。

### E.2 DCM 无插入路径（**M1 不落此点**）

- 全文件 8 处 `insertAdjacentHTML`，**DCM 零处**（`:9229` + `:11080/11113/11140` + `:13823-13826`）。
- 点检只两条路径：① `openMtExec`(`:15536-15540`) **就地改既有行**；② `openMtPlan` 保存**只弹 toast**（`:15572-1574`）。
- 🔴 tab 计数（`:5815-5819` 的 8/3/1/2/2）是**静态文本，全文件无一处 JS 回写**（对照 `:3358-3363` 的 `id="woCnt-*"` 才是有回写的模式）。

⇒ **注入 DCM 行必然使 tab 数字失真**（= 界面上看起来坏了）。
**决定**：M1 只在 A.1 落单；DCM 落点延到 M2，届时三选一（升用户或记决策）：
(a) 只就地更新既有行的「最近执行」，不新增行；
(b) 新增行 + 由 loader **一并回写 tab 计数**（代价：我们替原型写了它没有的逻辑）；
(c) 不做 DCM。

#### ✅ E.2 裁决（**v1.8 · 2026-09-28 关闭**）：选 **(c) 不做 DCM**

**理由双重，任一条单独成立即足以关闭：**

| # | 理由 | 依据 |
|---|---|---|
| 1 | **输入根本产不出来** | §C.3 / v1.7：夹具只可用「人员违规」；而 DCM 落点的两类输入（**仪表读数 / 设备渗漏**）上游**当前产不出结论**。硬做＝**描述不存在的输入**（D-018 同形） |
| 2 | **原型无插入路径** | 本 §E.2 上半：全文件 8 处 `insertAdjacentHTML` **DCM 零处**；tab 计数是**静态文本、全文无 JS 回写** |

⇒ **DCM 落点整条线关闭**，不是"延后"。原设计里「仪表读数 → 设备点检记录」这条桥**不成立**：
既没有可读的表，也没有可写的位。

> **本条的账要记在作者头上**：`mes-team.md` 与本文 A.2 曾把 DCM 列为第二落点，
> 那是**在核上游能力边界之前**写的。**与「7 处自相矛盾」同一根因**——
> 写下要求时没有回到真实系统核它可不可行。

## F · 失败可见性（**禁止静默失败**）

> 本阶段的头号风险是**静默失败**：字段名不一致 → 什么都没渲染 → 界面上看起来"没发生任何事"。
> 参照 `decision-log.md` D-027 教训 2：「只改管线而不改界面，则故障在界面上仍然长得像「没事」」。

| 情形 | loader 必须做 |
|---|---|
| `schema_version` 不认识 | **渲染可见错误横幅**，写明期望版本与实际版本 |
| JSON 解析失败 | 同上，带文件名 |
| `dept` 不在枚举内 | **跳过该条并横幅列出**，不得静默丢弃 |
| `kind` 未知 | 跳过（本版约定行为），但**计数并在横幅标注** |
| `records` 为空数组 | **不报错**（合法的"无新单据"），但 stdout 说明 |
| `inbox.json` 不存在 | **静默**（离线双击的合法场景），不报错 |
