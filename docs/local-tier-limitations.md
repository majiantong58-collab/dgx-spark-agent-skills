# 本地三层（Tier 0 / 0.5 / 1）局限与已知缺口

> 本文供并入 `docs/DELIVERY.md` 的「局限」节。所有条目均为实测得到，不是推测。
> 生成依据：`skills/safety-hazard-detection/scripts/local_tier_pipeline.py` 在三张实拍照片上的运行结果。

## 1. Tier 0.5（颜色/几何启发式）的能力边界：能确认「有」，不能断言「无」

启发式看不到蓝色，只能说明它没看见蓝色——**它在当前配置下看不见白色着装**。
白色掩膜里混有大量噪声连通块（墙面、机柜、反光全在其中），
对白色人员的**召回为 0**。因此「没找到」不构成该人员未佩戴 PPE 的证据。

**但成因必须说清，否则会被误读成「设计约束」。这个 0 是**实现缺陷**，不是能力上限。**

| 事实 | 依据 |
|---|---|
| 站点参数把**帽子和衣服双双收成「只有蓝色」一个区间** | `local_tier_pipeline.py:55`（`SITE_PARAMS`） |
| 注释写明「白色区间本身饱和度为 0，**不能被它误杀**」 | `ppe_color_probe.py:105` |
| 而紧接其下的实现对**所有颜色区间的并集**统一施加 `sat_floor >= 60` | `ppe_color_probe.py:106-108` |
| 白色区间是 `S ∈ [0, 45]`；`45 < 60` ⇒ **恒被清零，与图像内容无关** | `ppe_color_probe.py:36` |
| 实测白色像素饱和度中位 **21**、90 分位 **38**（阈值 60）⇒ **存活率 0.0000** | 实跑 |
| 把白色区间加回去，输出与当前**逐位完全相同**（死代码的直接证据） | 实跑 |

- **注释与实现在同一处直接矛盾**：注释声明白色豁免，实现未给任何豁免。
- **量到的白色掩膜数字**（`0df3783c…jpg`，逐项复核，供他人复算）：

  | 口径 | 像素占比（未清理） | 清理后 | 面积 ≥400 的连通块 |
  |---|---|---|---|
  | 代码里的白色区间（`:36`，`S∈[0,45]`） | **9.58%** | 8.80% | **24** |
  | `probe_white_killed.py` 另设的白区间（`S∈[0,55]`） | **10.91%** | 10.01% | **22** |

  白色像素饱和度：**中位 20–21、90 分位 37–38**（两种口径），阈值 **60**。
  ⚠️ **早期文档写的「覆盖率 11.7% / 17 个连通块」在两种口径下都复算不出来**，
  已按上表替换；**若将来要再引用，请连口径一起写。**
- **后果**：车间里穿白色防护服的工人，系统从原理上看不见。
- **但修复后并不改变结论**：把缺失颜色区间补回后，
  **照片1** 的把握范围为 **0.08–0.46**（逐人 0.0832–0.4632）；
  **含照片2 时为 0.08–0.56**（照片2 那位到 0.5575）。
  **两种范围都全部低于 0.75 阈值**，故「本层不下结论」这一结论不变。
  **这属于「修了也不够」，不属于「设计如此」。**

在安全场景里**假指控比漏检更危险**：漏检只损失一次检查机会，
假指控会冤枉一个穿戴合规的人，并摧毁对系统的信任。

**实现约束**：Tier 0.5 只要没有正面证据，`severity` 一律为 `uncertain`，
**绝不允许**输出 `warning` / `critical`。
（实测：修复前 photo1 有 3 人被误标 `warning`，修复后全为 `uncertain`；
整轮 7 条 findings 中 `warning`/`critical` 出现 **0** 次。）

> ⚠️ **源码注释里的「除非 Tier 1 确认」当前未实现。**
> `local_tier_pipeline.py:176` 写的是「故本层**绝不允许**输出 warning / critical —— 除非 Tier 1 确认」，
> 但 findings 在 **`:185-203` 就已定稿**，Tier 1 是在 `:219` **之后**才被调用，
> 其输出只写进结果顶层 `tier1_answer`（`:246`），**不回写 `findings`**。
> 全仓库读该字段的只有 `ui/index.html` 的引文块与 `.scratch/` 下的探针。
> **结论：该从句描述的是设计意图，不是当前行为。**

**度量可达性**：`conf = min(helmet_cov, vest_cov)` 取最弱一环（`local_tier_pipeline.py:153`），
而头盔区仅占框高 **0.33**（`ppe_color_probe.py:60`）。
**在未打码的这批照片上**，实测头盔最大覆盖 **0.4632**、背心区最大覆盖可达 **0.8116**——
`0.4632` 来自 `min()` 的头盔那一项，**绑住这一批的是头盔项**；
7 条 findings 全部为 `uncertain`（最高 **0.4632**）。

> 🔴 **但该判定线是可越过的，不是结构上不可达。** 在**打码后**的同一张照片上，
> 实测把握达 **0.7525 > 0.75**，系统**确实输出过一条 `info`**
> （该轮 5 条：4 × `uncertain` + 1 × `info`）。见 `docs/face-blur-rerun-ledger.md` §1.3。
> **越线的不是「穿戴更规范」，是一次人脸马赛克** —— 说明该把握值是**未标定的覆盖率代理量**，
> **不得把「达到判定线」读作「本层认为此人合规」。**

**正面证据率必须随结论一起给**（**这不是召回率**——本场景无 ground truth）：
photo1 上启发式对 6 人中 3 人有正面证据，**3/6**。

## 2. `next_tier` 无法承载「需要自然语言描述」这一触发条件

`escalation-policy.md` §2 将「需要自然语言描述而 Tier 0 只给标签」列为
Tier 0 → 1 的独立触发条件，但 `next_tier(current, confidence, *, has_conflict)`
签名中没有对应形参。**policy 有定义、接口未承载。** 调用方需自行判定后直接指定层级。

## 3. `should_escalate_to_cloud` 无法判定 Tier 1 → 2 的触发条件

policy 的 Tier 2 触发条件是「同一帧 ≥3 个互相冲突的候选」与「需要成文报告措辞」，
二者都无法从该函数签名（只有 `current` / `confidence` / `budget`）推导。
**policy 有定义、接口未承载。**

当前实现是**闸门**而非触发器，只判定三条可判定项：
`cloud_authorized`、预算未耗尽、`current >= 1`（不越级）且 `confidence >= UNCERTAIN_CONFIDENCE`
（policy 明文：Tier 1 复核后仍低置信 → uncertain，不升 Tier 2）。
调用方必须在**已认定触发条件成立**的前提下调用本函数。**未臆造规则。**

## 4. `record_failure` 是累计计数，不是 policy 所说的「连续」失败

policy §4 写的是「同一子技能**连续**失败 2 次 → 停止重试」。
本模块没有 `record_success`，`BudgetState` 也无「上次结果」字段，
**无法实现成功的重置语义**。当前为累计计数。**实现与 policy 措辞存在偏差，已知悉。**

## 5. `summarize_budget` 无法计算「本地兜底率」

该指标是 policy 的核心目标（> 90%），但 `BudgetState` 只有
`tier2_calls` / `retries` / `wall_clock_ms`，**没有总任务数与本地解决数**。
因此 `local_fallback_rate` 输出 `None`，**不臆造数值**。
需调用方累计 `tasks_total` 与 `tasks_resolved_locally` 后才能计算。

## 6. 人数不可宣称精确

photo1 上 **YOLO 报 6 人、Tier 1 VLM 报 5 人**，两者不一致，**未逐像素人工复核，无法裁决谁对**
（YOLO 第 6 个框置信度仅 0.301，本就偏低）。不得宣称「精确计数」。
与报告模板既有的免责声明同性质。

**两点补充：**

1. **系统内不存在裁决环节。** `tier1_answer` 是自由文本，从未被解析为结构化计数
   与 YOLO 的框数比对——**分歧不会被任何代码发现，只会被读者发现。**
2. **不能改为「以 VLM 为准」。** 实测模型自述的计数**随提示词措辞变化**：
   同一帧、`do_sample=False`（确定性），
   原提示词（`local_tier_pipeline.py:57`）答 **5 人**，
   编号提示词（`.scratch/probe_prompt_numbering.py`）答 **6 人**。
   两次都稳定复现，说明**分歧不是随机抖动，是这个量本身不唯一**。

## 7. Tier 0 不认识任何 PPE 类别

COCO 版 yolo11n **没有「防尘帽 / 防静电服」类别**（也没有「安全帽 / 反光衣」）。
Tier 0 的职责仅为**人形定位与计数**，不作为 PPE 判定依据。
另外实测场景为**电子厂无尘车间**（蓝色防尘帽 + 蓝色防静电服），
与 `escalation-policy.md` 原有的工地假设（安全帽 / 反光衣）**不一致**，待场景确认后统一。

## 8. Tier 1 的输出**不参与判定链路**（对照实验）

**这是当前实现的既成事实，不是设计目标。**

| 环节 | 代码位置 | 事实 |
|---|---|---|
| findings 定稿 | `local_tier_pipeline.py:185-203` | 全部字段（`severity` 等）在此写死 |
| Tier 1 被调用 | `:219` | **在 findings 定稿之后** |
| 输出去向 | `:246` `result["tier1_answer"] = vlm_answer` | **只挂到结果顶层**，不回写 `findings` |
| 唯一消费者 | `ui/index.html:932` 的引文块 + `.scratch/` 探针 | **判定链路中无任何消费者** |

**决定性对照**：把「模型说全部合规」与「模型说 3 号没戴帽」分别喂进去，
**机器判定逐字段完全相同**。

**后果**：
- §1 的实现约束中「除非 Tier 1 确认」**无法生效**（见 §1）。
- 架构表里 Tier 1「确认或推翻 Tier 0.5」是**设计意图**。
- **该层目前是「描述者」，不是「判定者」**：它被调用、产生成本，
  但其输出不改变任何一条结论。

## 9. 故障曾伪装成「跳过 · 上游无信号」——✅ **已修复**（2026-09-28）

**问题**：`_yolo_person_boxes()` 在 `ultralytics` 未安装或权重文件缺失时
**返回空表而不抛异常** ⇒ 走 `local_tier_pipeline.py` 的「无人的帧」短路分支
⇒ 界面显示「跳过 · 上游无信号 / 上游未检测到人员区域」。
**整机检测挂掉，对外看起来是「画面里没有人」。二者当时不可区分。**

**修复**（两处配套改动）：

| 环节 | 改动 | 位置 |
|---|---|---|
| 探针 | 新增 `DetectorUnavailable`；`_yolo_person_boxes(..., strict=True)` 时**抛异常**而非返回空表 | `ppe_color_probe.py:218-244` |
| 管线 | 以 `strict=True` 调用并捕获；失败时写**另一条** `short_circuit` 码 `tier0_unavailable: …`，且 `calls["tier0"]` **保持 0**（不记成「跑过」） | `local_tier_pipeline.py:122-133` |
| 界面 | 失败显示「**未能运行**」，并注明「**这不代表画面里没有人**」 | `ui/index.html:482, 859, 891` |

**验证（本次实测，CPU、不加载模型）**：阻断 `ultralytics` 导入后调用 ——
`strict=False` 仍返回空表并打印 `[warn]`；`strict=True` **抛出 `DetectorUnavailable`**。
⇒ 「确实无人」与「检测器没跑起来」现已在**数据层与界面层都能分开**。

> ⚠️ **仍存在的边界**：探针 CLI 的**默认**仍是宽松行为（`strict=False` 返回空表）。
> 这是**刻意的**——它是独立命令行工具，不应因环境缺依赖而崩。
> 所以「用了默认值的调用方」仍会看到静默空表。**管线这条路径已用 `strict=True`。**

## 10. Tier 1 的逐人输出**未验证接地**（扰动对照，n=1）

**做法**：同一张编号图，**只**抹掉 1 号人形框顶部 20%（帽子所在区域），
制造一个**已知违规**；其余像素不变。

| 编号 | 基线（跑 2 次） | 扰动后（仅动 1 号框） |
|---|---|---|
| 1 | 是 | **是（未翻转）** |
| 2 | 是 | 是 |
| 3 | 是 | **否（翻转）** |
| 4 | 是 | **否（翻转）** |
| 5 | 是 | 是 |
| 6 | 是 | 是 |

原始记录：`.scratch/prompt_num.log`（基线）／`.scratch/grounding.log`（扰动）。

**结论**：改动**只发生在一个框内**，结论却**漂到了别的框上**，
而**被改的那个框自己没变**。

> **诚实边界**：n=1 帧、n=1 次扰动、扰动方式粗糙（整块涂抹）。
> **只够支持「不能假定它接地」，不够支持「它不可能接地」。**

## 11. 实拍照片已打码，**打码改变了检测结果**

演示用实拍照片含可辨认人脸（当事人未同意公开），已产出打码版
（`scripts/blur_faces.py` → `assets/real_photos/blurred/`）。**打码不是无操作的。**

| 量 | 打码前 | 打码后 |
|---|---|---|
| 照片1 人员区域 | 6 处 | **5 处** |
| 照片1 有人把握 | 0.4632 | **0.7525（越过 0.75 判定线）** |
| 另一张 人员区域 | 1 处 | **2 处**（同一人被检出两个重叠框） |

- 文档中**全部照片级数字取自未打码原图**（`local_tier_pipeline.py:280` 的非递归 glob
  排除 `blurred/`）。原图不随仓库分发 ⇒ **这些数字无法从可发布素材复现**。
- 上表打码后的数字**尚未落盘**（全仓库 grep 不到 `0.7525`）。**引用前必须先落盘。**
- **打码改变了检测结果——这件事本身就是一条证据**：
  检测链路对头部区域的像素扰动敏感。

## 12. 实验重做被基础设施阻塞（**不是零结果**）

- 原四臂实验：`Δ2 = 0.000`，四臂 FTR 全为 0 —— **不可解释**，见下「三个已知混淆」。
- 重做版（五臂 A/B/C/C′/D，46 用例 × 3 次 = **690 次调用**）：
  **预注册已冻结、执行器 `--selftest` PASS，但一次都没发出**
  （StepFun 账户配额耗尽，HTTP 402 `quota_exceeded`）。
- **判读状态 = 不可判读（基础设施阻塞）**，不是零结果、也不是有效应。

**三个已知混淆**（详见 `skills/evals/ablation-v2/STATUS.md` §3）：

1. **C 臂的操作根本没施加成功**——四个 `SKILL.md` 正文都有一节复述 description 的
   `不适用于：`，原 C 臂只删 description，**边界信息仍在上下文里**。
2. **主指标漏报**——A 臂实测广义触发率 0.562、幽灵技能调用 76 次，
   而「本技能口径」的 FTR 记成了 0.000。
3. **负例偏易**——原 16 条负例只有 6 条是真 near-miss。

> **因此「未观测到负向条件的运行时收益」这一表述当前不成立**：
> 不是「测了没有效应」，是**变量没施加成功**。
