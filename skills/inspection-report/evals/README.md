# evals — inspection-report

## 用例字段

| 字段 | 说明 |
|---|---|
| `id` | 用例编号 |
| `type` | `positive` 应触发 / `negative` **正确答案是不调用本技能** / `positive_empty` 应触发但产出被裁剪 |
| `expect_trigger` | 本技能是否**应当被调用** |
| `expect_route` | 不该触发时，正确的去向；`[]` 表示谁都不调用 |
| `expect_sections` | 期望出现的报告小节 |
| `expect_source` | 期望的结论来源标记（如 `user`） |

## 三条轴的区分

1. **`negative`（4 条）** —— 正确答案是**不调用本技能**。
2. **`positive`（5 条）** —— 应触发并产出合规报告。
3. **`positive_empty`（1 条）** —— `report-empty-001`：上游 5 条中 2 条缺 `confidence`，
   应触发但必须**拒收那 2 条并显式回报**——不得静默丢弃，也不得补造置信度。

## 负向用例的理由

| id | 不该触发的原因 |
|---|---|
| `report-neg-001` | 原始图像要从零识别——本技能**不识别、不读数、不新增结论** |
| `report-neg-002` | 单一读表请求，与成文无关 |
| `report-neg-003` | 通用文案写作——本技能只服务巡检数据 |
| `report-neg-004` | 含「报告」字样但**无巡检数据**（季度安全生产工作总结）：本技能只把已有巡检结论成文，不代写通用公文 |

## 评分

| 指标 | 口径 |
|---|---|
| 触发准确率 | `expect_trigger` 判定正确率 |
| 负向误触发率 FTR | 负例中被错误调用的占比 |
| **幻觉项数** | 报告中无法回溯到输入的条目数（应为 0）——本技能的首要指标 |
| 建议合规率 | `recommendation` 逐字来自 `severity-levels.md` 映射表的占比（应为 100%） |
| 免责声明覆盖率 | 页脚含免责原文的占比（应为 100%） |
| `uncertain` 保留率 | 上游 uncertain 条目在报告中未被清洗的占比（应为 100%） |
| 身份信息泄漏数 | 报告中出现的身份类字段数量（应为 0） |
| Schema 合规率 | 字段不增不删、缺值用 `null`/`未指定` 的占比 |
