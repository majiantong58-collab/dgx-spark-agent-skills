# 巡检报告生成（Inspection Report）

只做一件事：**把结构化巡检结论渲染成报告**。不识别、不读数、不新增任何结论。

## Purpose

把已完成的隐患识别与仪表读数结果汇总成结构化巡检报告，包含分级与整改建议，并支持导出 Markdown/JSON。

## 前置问题（缺一不可，禁止猜测）

1. **巡检点位 / 设备编号？** 缺失则写 `未指定`，**禁止编造点位名称**。
2. **巡检人与巡检时间？** 缺失则留空待填，**禁止用当前时间冒充巡检时间**。
3. **报告用途？** 内部整改 / 上报监管——决定详略与是否需要引用条款。
4. **数据来源？** 必须来自上游子技能的结构化结果；用户直接口述的结论须标 `source: "user"`。

## 主流程

1. **校验输入** — 每条结论必须含 `hazard_code` 或 `gauge_id` **且含 `confidence`**；
   缺置信度的条目一律拒绝入报告并回报，不静默丢弃。
2. **安全边界（前置，不是最后一步）**
   - **不得新增上游未给出的结论**，本技能只做汇总、分级与措辞。
   - 低置信条目必须原样标注 `uncertain`，**不得在报告里被"洗干净"**。
   - 涉及人员违规时**不得出现任何身份信息**，只写行为与 PPE 状态。
   - 报告页脚强制含免责声明，逐字取自 `references/output-schema.md` §4（**单一措辞来源**），不得改写或缩写。
   - 未经授权不得把巡检原始图像或点位台账送云端。
3. **分级排序**（`references/severity-levels.md`）：按 `severity` 排序，高在前，同级按点位号。
4. **生成整改建议** — 只从 `references/severity-levels.md` 的规则表映射，**不做自由发挥**。
5. **渲染** — `scripts/assemble_sections.py` 组装 → `scripts/render_markdown.py` 输出，Schema 见
   `references/output-schema.md`。
6. **回读校验** — 报告中每条结论必须能在输入里找到对应项，找不到即报错并中止输出。
7. **返回 Markdown + JSON 双份**，附 `uncertain_count` 与 `partial: bool`。

## 输出契约

严格遵循 `references/output-schema.md`，不增字段、不省略字段。

## 负向边界（何时本技能不该被调用）

- 用户给的是原始图像并问"有什么问题" → 不调用，交 `safety-hazard-detection`。
- 用户要读一个表的值 → 不调用，交 `gauge-reading`。
- 用户要的是营销文案、周报、新闻稿、代码 → 不调用，本技能只服务巡检数据。
- 只有一条口头结论且用户没要求成文 → 不调用，直接回答即可。
