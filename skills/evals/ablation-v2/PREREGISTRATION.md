## 0. 为什么要重做（三个已知混淆）

原四臂实验（`skills/evals/results/`，v1 描述）得到 `Δ2 = FTR(C) − FTR(B) = 0.000`，
四臂 FTR 全为 0。该结果**不可解释**，因为：

1. **C 臂的操作没施加成功。** 四个 `SKILL.md` 的**正文**都有
   `## 负向边界（何时本技能不该被调用）` 段，逐条复述 description 的 `不适用于：` 内容。
   原 C 臂只从 description 删 `不适用于：` 句，正文照常加载 → **边界信息仍在上下文里**。

2. **主指标漏报。** A 臂（裸模型）广义触发率 0.562、幽灵技能调用 76 次，

3. **负例偏易。** 16 条负例中真 near-miss 少；裸模型都不误触发的负例，测不出任何操作的效果。

另有版本问题：原结果跑在 **v1 描述**上，仓库现在是 **v2**（场景对齐为电子厂房洁净车间）。

## 3. 口径与聚合（预先冻结）

- 调用：模型 `step-5-preview`，`temperature=0`，`USER_TEMPLATE` 与 `run_comparison.py` 逐字一致。
- 每条用例重复 **3 次**（与原设计一致，便于对照）。
- 聚合：`majority`（`触发次数 × 2 ≥ 有效运行数`，平票按触发）为主口径；
  `any` / `all` 三种口径**全部并列报告**。
- **主指标（本技能口径）**：负例中「该用例 `skill` 字段所指技能」被误调用 ——
  逐次判定后取票。**保留原口径，继续报告。**
- **并列报告（诊断口径，不替代主指标）**：
  - **广义触发率**：任何技能被调用即算误触发（分母同为负例数）。
  - **幽灵技能计数**：`skills` 里出现本项目不存在的技能名
    （定义与 `run_comparison.py:599` 一致：对**全部运行**计数，不只负例 —— 以保持与历史 76 次可比）。
- 主结论量：**Δ2′ = FTR_own(C′) − FTR_own(B)**（正值 = Not-for 段有净收益）。
- 原量并列：**Δ2 = FTR_own(C) − FTR_own(B)**。

### 预先冻结的三个分析子集

| 子集 | 成员 | 角色 |
|---|---|---|
| **S1** | 全部 22 条负例 | **主口径**。禁止事后增删任何一条 |
| **S2** | 新增 6 条硬负例 | 敏感性分析 |
| **S3** | Not-for 可判别子集 = 22 条 **去掉** `hard-gauge-neg-001` = **21 条** | 敏感性分析 |

S3 的成员判定规则（现在写死）：**该技能 description 的 `不适用于：` 列表是否字面覆盖本条的正确拒绝理由**。
逐条核对结果：原 16 条全部覆盖；新 6 条中只有 `hard-gauge-neg-001` 不覆盖。故 S3 = 21 条。

### 次要指标（更细粒度，用于提功效）

**Δ2′_runs = mean over S1 的 (C′ 逐次运行本技能误触发率) − (B 逐次运行本技能误触发率)**
分母 = 22 × 3 = **66 个运行级观测**，分辨率 1/66。

## 4. 判读规则（**跑之前写死，跑完不许改**）

### 4.1 分辨率

| 量 | 分母 | 最小非零步长 |
|---|---|---|
| Δ2′（case 级，majority-of-3） | 22 条负例 | **1/22 = 0.0455** |
| Δ2′_runs（run 级） | 66 次运行 | **1/66 = 0.0152** |
| Δ2′（含相关对 gauge-neg-001 / report-neg-001） | 22 条 | 同一输入翻转 → 一次动 **2/22 = 0.0909** |

> `gauge-neg-001` 与 `report-neg-001` 输入完全相同（原 README 已记载），二者**同向相关**：
> 该输入一旦判错，同时在两个技能上各计 1 条。故该输入的效应是普通负例的两倍。

### 4.2 判定表

| 观测 | 判定 | 措辞 |
|---|---|---|
| Δ2′ ≥ **+1/22** 且三种聚合口径下同号 | **有效应（正向）** | Not-for 段有净收益，最小可测幅度 +0.045 |
| Δ2′ ≤ **−1/22** 且三种聚合口径下同号 | **有效应（反向）** | 删 Not-for 反而降低误触发 —— 与假设相反，按异常/混淆解释，**不得反过来当成 Not-for 有价值的证据** |
| Δ2′ = **0** | **零结果** | 未观测到差异 |
| 三种聚合口径**正负号不一致** | **随口径反转** | 如实并列三种口径，不得只报 majority |
| 负例有效样本缺失 / 有调用失败 / 有解析失败 | **不可判读** | 按 `run_comparison.py` 的 `reliable` 字段判定 |

### 4.3 零结果时的「可排除效应下限」

若 Δ2′ = 0，则**排除**「真实效应 ≥ 1/22 = 0.0455 且会翻转 ≥1 条负例」的情形；
**无法排除**小于 0.0455 的效应。另给两个更细的界：

- **run 级界**：Δ2′_runs = 0 时，排除效应 ≥ 1/66 = 0.0152。
- **统计上界（rule of three）**：若 C′ 在 22 条负例上观测到 0 条误触发，
  则 C′ 真实误触发率 95% 上界 ≈ 3/22 = **0.136**；B 同理。两者之差的上界据此给出。

### 4.4 禁止事项（写下以便对照执行）

- 不得因结果不显著而增删负例、改分母、换主指标。
- 不得只报广义口径或只报本技能口径 —— **两个口径必须并排出现**。
- 不得只报最好一次运行。
- 不得把 S2 / S3 的结论当主结论报（它们是敏感性分析，必须标注）。
- 若 C′ 与 B 的差异只出现在 `hard-gauge-neg-001` 上，须明说该条不由 Not-for 判别。

主实验开跑**之前**，先跑一个门禁：**A / B / C 三臂 × 原 16 条负例 × 3 次 = 144 次调用**。

通过条件（与 `skills/evals/results/report.md` 对照）：

| 检查项 | 历史值 | 通过条件 |
|---|---|---|
| A 臂广义触发率（16 条负例） | 0.562 | 落在 0.562 ± 0.125（即 7/16 ~ 11/16） |
| B 臂本技能口径 FTR | 0.000 | = 0.000 |
| C 臂本技能口径 FTR | 0.000 | = 0.000 |
| A 臂幽灵技能次数（仅这 48 次运行内） | — | 记录值，不设门禁（定义域不同，见下） |

> 幽灵技能 76 次的历史值定义在**全部 40 条用例 × 3 次 = 120 次运行**上，
> 而门禁只跑 16 条负例，**分母不同、不可直接比**。门禁只记录，不设通过线。
> 76 次的复现检查在主实验的 A 臂（46 条用例 × 3 次）上做，但那已含新用例，故按
> **原 40 条用例子集**重算后方可与 76 比对 —— 该比对作为**主实验的一部分**报告。

**门禁不通过 → 停止，不跑主实验，先报告差异。**
