## 4. 三个已知的诚实边界

### 边界 1：两条 orch 硬负例词面偏弱

机械核验（只测 `input` 行，**不拿 `assets` 凑命中** —— 触发词必须落在任务行才算 near-miss）：

| 用例 | 任务行命中核心词 | 命中数 |
|---|---|---|
| `hard-hazard-neg-001` | 防尘帽、洁净车间、车间 | 3 |
| `hard-hazard-neg-002` | 防尘帽、防静电服 | 2 |
| `hard-report-neg-001` | 巡检报告、报告 | 2 |
| `hard-gauge-neg-001` | 压力、压力表、照片 | 3 |
| `hard-orch-neg-001` | 巡检 | **1（偏弱）** |
| `hard-orch-neg-002` | （无） | **0（弱）** |

**保留不改。理由：改了就是动预注册。** 用例清单在 `PREREGISTRATION.md` §2 逐条写死，
现在删改会破坏冻结纪律。两条 orch 负例测的不是词面而是**路由语义**（orch 只在三件事
**未指明**时才触发），已在 `PREREGISTRATION-ADDENDUM-1.md`（22:52，**跑之前**）记录。

**判读时必须单独标注**：若 Δ2′ 的效应只体现在 hazard/report/gauge 的负例上，
**不得据 orch 的零差异声称「orch 的 Not-for 无用」**。

### 边界 2：C′ 有个消不掉的耦合

C′ 删掉的那段正文里**同时含兄弟技能名**（「交 `gauge-reading`」「交 `inspection-report`」）。
故 C′ 相对 B **同时**少了两样东西：

- (a) **域排除条件** —— 这是我们要测的
- (b) **路由提示**（兄弟技能名）—— 这是搭便车的

**两个变量被绑在一起，无法分离。**
→ 若 C′ 的**广义**触发率上升而**本技能**触发率不变，优先怀疑 (b)，不是 (a)。

### 边界 3：残留边界线索（**若 Δ2′ 仍为 0，这是首要候选解释**）

四个正文首段仍有「只做一件事：…**不读数、不成文、不做趋势分析**」这类**正向范围陈述**。
它隐含边界信息，本轮**不删** —— 删掉就等于删掉技能的定义本身。

**→ 若重做后 Δ2′ 仍为 0，这一条是「零结果仍不可解释」的首要候选解释**，
必须在报告里明说，不得反过来声称「已证明 Not-for 无用」。

## 5. 换 key / 换模型时的评估顺序（团队已定，待命中）

配额恢复（或拿到新 key）后，**先评估、再动手**，按此顺序回答三个问题：

1. **是不是同一个 `step-5-preview`**（同厂商同版本 vs 完全是另一个模型）。
2. **原四臂的复现门禁还能不能过** —— 若新执行体在 A 臂上复现不出历史
   **广义触发率 0.562 / 幽灵技能 76 次**那个量级的行为，则 C′ 与 B 的差值**没有共同基准**，
   与 v1 历史的对照不成立。
3. **门禁过不了还能不能做** —— 退而求其次：**只在同一个新执行体内部做五臂对照**，
   并明确标注「**本轮内部自洽，但不与 v1 历史对照**」。

> **取舍原则（团队定调）**：宁可要一个「**范围缩小但自洽**」的结果，
> 也不要一个「**硬凑着跟历史比**」的结果。

**关键前提**：换 key = 换执行体，不只是换凭据。「与 v1 历史可比」这个前提**要重新评估，不能默认继承**。
