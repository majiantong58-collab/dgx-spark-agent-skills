## 2. 为什么改（**三条理由，任一条独立成立**）

### 2.1 数字不可复核

「**白色掩膜覆盖率 11.7%、17 个噪声连通块**」首次出现于首版提交 `ccbe393`，
之后从未被修改：

```
git log -S "11.7%" --all  →  ccbe393  2026-09-27
```

**独立复算（CPU，两种口径）都得不到这两个数**（对象 `0df3783c….jpg`）：

| 口径 | 像素占比（未清理） | 清理后 | 面积 ≥400 的连通块 |
|---|---|---|---|
| 代码里的白色区间（`ppe_color_probe.py:36`，`S∈[0,45]`） | **9.58%** | 8.80% | **24** |
| `probe_white_killed.py` 另设的白区间（`S∈[0,55]`） | **10.91%** | 10.01% | **22** |

**两种口径都得不到 11.7%，也得不到 17。** 原始测量条件从未记录 ⇒ **不可复核**。
**留一个没人能验证的数，比留一个已更正的数危险。**

### 2.2 因果归因是反的

原文把「白色召回为 0」写成「实测边界」（隐含「设计如此、不可修」）。
**实际是两处独立的实现缺陷**：

| # | 缺陷 | 位置 | 性质 |
|---|---|---|---|
| 1 | 对所有颜色区间**并集**统一施加 `sat_floor >= 60`，白色区间 `S∈[0,45]` **恒被清零** | `ppe_color_probe.py:106-108` | **算术必然**：交集为空，与图像内容无关 |
| 2 | `SITE_PARAMS` 把 helmet/vest **双双覆盖成只有蓝色**，白色区间**根本没被选中** | `local_tier_pipeline.py:55` | 参数化排除 |

**两处独立死因**说明这不是一处笔误。且缺陷 1 与源码自身注释
（`:105`「白色区间本身饱和度为 0，**不能被它误杀**」）**直接矛盾**。

**更硬的一条**：`ppe-rules.md:15` 的场景表自己写着
「防尘帽、防静电服（**蓝色或白色**）」——**技能自己的参考文件声明白色在范围内，
实现却把它排除了两次。**

### 2.3 有一句是**假的能力声明**，而不只是错数字

原文「**白色着装只能交 Tier 1 VLM 判定**」——**这句是假的**：
Tier 1 的输出**不参与判定链路**（findings 在 `local_tier_pipeline.py:185-203` 就已定稿，
Tier 1 在 `:219` 之后才被调用，输出只写结果顶层 `tier1_answer`，**不回写 findings**；
全仓库唯一消费者是 `ui/index.html:932` 的引文块）。

> **这一段不是「数字过时」，是「在交付给评审的技能文件里承诺了一个不存在的兜底路径」。**
> 这已经超出预注册保护的范畴。

## 3. 机械验证：改动是**臂不变**的（已执行，非承诺）

### 3.1 载荷构成

`run_ablation.skill_payload_v2()` 对 `safety-hazard-detection` 的载荷只含三部分：
`SKILL.md` ＋ `hazard-taxonomy.md` ＋ **`references/ppe-rules.md`**。
**`scripts/local_tier_pipeline.py` 不在载荷内**（已 grep 验证）⇒ 改动 #2 无载荷影响。

### 3.2 改动前后逐字节比对（16 个载荷全量）

| 项 | 结果 |
|---|---|
| 16 个载荷中有变化的 | **3 个**（全部为 `safety-hazard-detection` 的 **B / C / C′**） |
| 未变化 | 其余 **13 个**（另三个技能的 12 个 ＋ `safety-hazard-detection__D`） |

`…__D` 未变是**正确的**：D 臂载荷只有 description，不含 references。

**改动前哈希**（`sha256[:16]`）：

| 载荷 | before | after |
|---|---|---|
| `safety-hazard-detection__B` | `5c1d9d856d64afa7` | `1edb84f2d2425f16` |
| `safety-hazard-detection__C` | `463a22021185983e` | `2d2eba4d659bdfa6` |
| `safety-hazard-detection__Cp` | `a2369c1e47ce741c` | `706f5e427f0f12a4` |

完整哈希清单：`.scratch/audit_pre_edit_payload_hashes.json` / `.scratch/audit_post_edit_payload_hashes.json`
（改动前另有一步核对：**16 个快照与当时文件重生成结果逐字节相同**，确认快照是新鲜的，
故上述差异**只能归因于本次改动**。）

### 3.3 **臂不变性**（这是关键结论）

**变化的 8 行，在 B / C / C′ 三臂上逐字节相同**（程序比对结果：`与基准相同: True`）。

```
- 白色掩膜覆盖率 11.7%、17 个噪声连通块（墙面、机柜、反光全在其中），
- 白色着装的人员召回为 **0**。白色着装只能交 Tier 1 VLM 判定。
- 完整能力边界见 `docs/local-tier-limitations.md`。
+ 白色掩膜里混有大量噪声连通块（墙面、机柜、反光全在其中），白色着装的人员召回为 **0**。
+ **「没找到白色」不构成「未佩戴」的证据**，本层对白色着装只能输出 `uncertain`。
+ **成因是实现缺陷，不是设计约束**：白色区间被饱和度下限整体清零，
+ 且站点参数只配了蓝色区间。详见 `docs/local-tier-limitations.md` §1。
+ 完整能力边界见同文件。
```

**为什么这一条就够**：

- 被改的段落**不含 `不适用本清单`**（C′ 的剥离条件是这一串），
  故 C′ 的**剥离行为不变** —— 删掉的段还是那些，没多删也没少删。
- 该段在**处理臂（C′）与对照臂（B）中完全相同** ⇒ **处理与对照的差异没有被触碰**。
  `Δ2′ = FTR(C′) − FTR(B)` 的对照结构**保持不变**。
- 同理 `Δ2 = FTR(C) − FTR(B)` 也不变。
- **本改动只可能影响「各臂的绝对触发表面」，不可能影响「臂间差值」** ——
  因为三臂拿到的是同一段新文本。

### 3.4 `--selftest` 的核心不变量**仍然成立**（已复验）

`STATUS.md` 记录 `--selftest` 核验过：「A/B/C/D 四臂载荷与**原执行器**逐字节一致」。
本次更正后**重新逐臂比对两个执行器**，该性质未受影响：

| 臂 | `run_comparison.skill_payload`（v1 执行器） | `run_ablation.skill_payload_v2`（v2 执行器） | 逐字节相同 |
|---|---|---|---|
| B | 4338 B | 4338 B | ✅ |
| C | 4275 B | 4275 B | ✅ |
| D | 216 B | 216 B | ✅ |

**原因**：两个执行器读的是**同一个文件**，文件改了，两边**同步改**，等式依然成立。
⇒ **本次更正不会破坏 `--selftest` 的「只多了 C′ 这一个变量」保证。**

## 4. ⚠️ 对原定验证方案的一处更正（**重要**）

**原方案**：「配额恢复后，先跑一次 **A 臂**复现门禁，确认这次材料改动行为上是惰性的。」

**这个方案无法达到目的。** 依据（`run_ablation.py:131-132`）：

```python
def skill_payload_v2(skill: str, arm: str) -> str:
    if arm == "A":
        return ""
```

**A 臂载荷是空字符串** —— 它**不加载任何技能内容**，因此
**对 `ppe-rules.md` 的任何改动都不敏感**。实测也印证：`.scratch/ablation-v2/cprime_payloads/`
下**没有 A 臂载荷文件**（只有 B/C/C′/D 共 16 个）。

> **跑 A 臂门禁必然通过，但它通过的是一条与本次改动无关的路径 ——
> 那会给出「已验证无害」的假保证，比不验证更糟。**

### 正确的验证（已执行，无需 API）

**§3 的载荷逐字节比对 ＋ 臂不变性证明**，是**当下就能做、且直接针对本改动**的验证。
它比 A 臂门禁强，因为：

| | A 臂门禁 | §3 臂不变性证明 |
|---|---|---|
| 需要 API / 配额 | **需要** | **不需要**（已做完） |
| 能感知本次改动吗 | ❌ **不能**（载荷为空） | ✅ 直接比对字节 |
| 结论强度 | 间接、可被巧合通过 | 逻辑必然 |

### 仍需 API 的验证（**保留为待办，但换了目的**）

B 臂重跑仍有价值，但目的**不是**验证本次改动，而是**验证执行体是否与 v1 同一**
（`STATUS.md` §5 已列为「换 key / 换模型时的评估顺序」第 2 条）。
**不要把这两件事混为一谈。**

## 6. 诚实边界

1. **本附注 §3 的验证是「静态」的**：它证明的是**载荷字节层面的臂不变性**，
   **不是**「模型行为不变」。后者需要跑 API，本轮做不到。
   但本改动的性质（三臂拿到同一段新文本）使得**行为层的不一致只可能来自噪声，不可能来自处理效应**。
2. **本次更正发生在实验尚未运行之时**：**690 次调用一次都没发出**
   （配额 402，见 `STATUS.md` §1、`results/GATE-OUTCOME.md`）。
   **因此不存在「先看结果再改材料」的可能** —— 这正是本附注要留痕的原因。
3. **本更正不改变任何已发表的数字**：11.7% / 17 从未进入任何实验结果文件，
   只出现在文档与载荷文本中。
4. **`skills/evals/results/`（v1 历史证据）本次一个字节未动**，已核对。
