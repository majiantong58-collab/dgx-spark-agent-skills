## 负例输入的重复相关性（读 `Δ2` 前必看）

`gauge-neg-001`（`gauge-reading`）与 `report-neg-001`（`inspection-report`）
的**输入文本完全相同**（「看看这张车间照有什么问题」），
因此 16 条负例实际只有 **15 个不同输入**。

**这是有意设计，不要改用例**：该输入既不归 `gauge-reading`、也不归 `inspection-report`，
两个技能都不该被触发——两条用例各自考核**本技能**的 `description` 是否拦住了它。
拆成两个不同输入会削弱各自技能的负向覆盖，反而动摇 `Δ2` 的实验基础。

**对 `Δ2` 读数的影响**：这两条用例**同向相关**。
按 16 条负例的 FTR 口径，同一输入一旦判错，会**同时**在两个技能上各计 1 条误触发——
最多给分子贡献 **2 条**，即 FTR 一次性变动 `2/16 = 0.125`，
是普通负例（`1/16 = 0.0625`）的**两倍**；`Δ2 = FTR(C) − FTR(B)` 相应一次跳动最多 0.125。

**处置**：`Δ2` 出现异常跳变时，先单独回看 `gauge-neg-001` / `report-neg-001` 是否翻转，
再解释其余用例；逐用例附录（`comparison-design.md` §4.3）中这两条必须相邻列出。
