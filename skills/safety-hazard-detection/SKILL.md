# 安全隐患识别（Safety Hazard Detection）

只做一件事：**从图像中判定"是否存在已定义的安全隐患"**。不读数、不成文、不做趋势分析。

## Purpose

从工业巡检图像中识别人身安全违规与现场隐患。
人员 PPE 类覆盖**未戴防尘帽、未穿防静电服**（电子厂洁净车间，v2 主场景）与
**未戴安全帽、未穿反光衣**（工地，v1 遗留，保留以便对照 v1 实验结果）；
现场类覆盖违规闯入、通道堵塞、设备渗漏、明火烟雾。

## 前置问题（缺一不可，禁止猜测）

1. **场景类型？** 洁净车间 / 生产车间 / 工地 / 仓储 / 配电房——不同场景的隐患清单不同（见 `references/ppe-rules.md`）。
2. **判定标准版本？** 未指定则默认 `references/hazard-taxonomy.md` 当前版本，并在结果里回标版本号。
3. **是否需要定位框？** 需要 → 输出 `evidence_bbox`；不需要 → 只输出标签，省算力。
4. **场景中是否可能有人？** 明确无人的场景跳过 PPE 类判定，避免误报。

## 主流程

1. **输入校验** — 尺寸、清晰度、是否可解码；不可解码直接返回错误，不硬猜。
2. **安全边界（前置，不是最后一步）**
   - 只判"行为 + PPE 状态"，**禁止识别人脸与身份**，不得输出任何可关联到个人的特征。
   - 遮挡 / 过曝 / 分辨率不足 → 标 `uncertain`，**禁止编造**未观察到的隐患。
   - 未获授权不得调用云端模型，与编排层授权状态一致。
   - 输出必须携带免责字段，逐字取自 `inspection-report/references/output-schema.md` §4（**单一措辞来源**），不得改写或缩写。
3. **调用检测器**（`scripts/detect_hazards.py`，Tier 0）得到候选框与置信度。
4. **按阈值分流**
   - `conf ≥ 0.75` → 采纳为 Tier 0 结论。
   - `0.40 ≤ conf < 0.75` → 升 Tier 1 本地 VLM 复核。
   - `conf < 0.40` → 丢弃，不报。
5. **去重与合并** — 同一目标多帧命中只保留一条（`scripts/dedupe_tracks.py`）。
6. **套用判定标准** — 按 taxonomy 给出 `hazard_code` / `severity` / `evidence_bbox` / `note`。
7. **返回结构化结果**并交回编排层；**本技能不写报告**。

## 输出契约

```json
[{"hazard_code": "PPE-NO-CAP", "label": "未戴防尘帽", "severity": "high",
  "confidence": 0.91, "tier": 0, "evidence_bbox": [x1,y1,x2,y2],
  "uncertain": false, "requires_human_review": true}]
```

## 负向边界（何时本技能不该被调用）

- 图里只有文档、表格、纯文字 → 不调用（无隐患语义）。
- 只问"这个表读数是多少" → 不调用，交 `gauge-reading`。
- 问的是"帮我看看这段巡检记录写得对不对" → 不调用，交 `inspection-report`。
- 场景够清晰但**无任何隐患** → 仍然调用，返回空列表；这是"零发现"，不是"不该调用"。
