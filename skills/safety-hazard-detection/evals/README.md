# evals — safety-hazard-detection

## 用例字段

| 字段 | 说明 |
|---|---|
| `id` | 用例编号，`<skill缩写>-<类型>-<序号>` |
| `type` | `positive` 应触发 / `negative` **正确答案是不调用本技能** / `positive_empty` 应触发但期望空或不确定结论 |
| `expect_trigger` | 本技能是否**应当被调用**（唯一的路由判据） |
| `expect_route` | 不该触发时，正确的去向；`[]` 表示谁都不调用 |
| `expect_codes` | 正向用例期望输出的 hazard_code；`[]` 表示期望零发现 |
| `expect` / `rationale` | 期望行为与设计理由，供人工复核 |

> `assets` 字段描述的是**需要准备的测试素材**，不是随仓库分发的图像。

## 三条轴的区分（关键）

1. **`negative`（4 条）** —— 正确答案是**根本不调用**本技能。这是讲师强调的负向用例。
2. **`positive`（5 条）** —— 应触发且应给出具体结论。
3. **`positive_empty`（1 条）** —— **应触发**，但正确输出是**空列表或不确定**。
   `hazard-empty-001` 测的是假阳性：干净车间不得被编造出隐患。
   它与负例不同——负例不改调用，此例必须调用但结论为空。

## 负向用例的理由

| id | 不该触发的原因 |
|---|---|
| `hazard-neg-001` | 纯文字 SOP 扫描件。**「有图」不等于「有隐患语义」**——这是本技能最容易被误触发的形态 |
| `hazard-neg-002` | 仪表读数属 `gauge-reading` 的窄触发区 |
| `hazard-neg-003` | 已有结论要成文，重跑识别会重复计费并可能造出新结论 |
| `hazard-neg-004` | 纯文本知识问答，无图像输入 |

## 评分

| 指标 | 口径 |
|---|---|
| 触发准确率 | `expect_trigger` 判定正确的用例占比 |
| **负向误触发率 FTR** | 负例中被错误调用的占比 —— **本技能的核心指标** |
| 结论正确率 | `expect_codes` 与实际输出集合的精确匹配率 |
| 假阳性率 | `positive_empty` 用例中输出了非必报结论的占比 |
| 编码合规率 | 输出中不在 `hazard-taxonomy.md` 内的 hazard_code 占比（应为 0） |
| 隐私违规数 | 输出中出现的身份类字段数量（应为 0） |

## 执行

由 A5 统一执行，对照方案见 `../../evals/comparison-design.md`。
每个用例重复 ≥3 次以观察触发稳定性（官方承认的痛点之一）。
