# 巡检编排（Inspection Orchestrator）

本技能**只做输入规范化、路由与编排，不含任何识别业务逻辑**。识别一律下沉到子技能。

## Purpose

工业安全巡检的总入口与窄路由层。接收巡检图像/视频帧或巡检任务，在未指明具体识别类型时分派到隐患识别、仪表读数、报告生成三个子技能，并决定本地/云端推理层级。

## 前置问题（信息不全时必须先问，禁止猜测）

1. **输入是什么？** 单图 / 视频序列 / 摄像头流 / 仅有文字描述？
2. **要看什么？** 隐患 / 仪表 / 报告。用户没说就按下方路由表判定；判定不了就**问**，不要默认全跑。
3. **图像可上传云端吗？** 未获明确授权 → 锁定 Tier 0/1，禁止调用 StepFun 云端模型。
4. **本次巡检的点位与设备台账？** 缺失时下游只写"未指定点位"，**不得编造**。

## 主流程

1. **规范化输入** — 校验图像可解码、分辨率、帧数；不合法即返回错误，不进入识别。
2. **安全边界检查（前置，不是最后一步）**
   - 未获云端上传授权 → 强制本地层级，**禁止外发任何像素**。
   - 禁止对人员做身份识别 / 人脸比对，只输出"人员"级别的行为与 PPE 状态。
   - 所有结论必须携带 `confidence`；低置信不得被下游升级为结论。
   - 本技能及其子技能的输出**不构成处罚、停机或联锁动作的唯一依据**（措辞逐字取自
     `inspection-report/references/output-schema.md` §4，**单一措辞来源**）。
3. **按路由表选技能**（详见 `references/routing-table.md`）
   - 人员违规 / 通道堵塞 / 设备渗漏 → `safety-hazard-detection`
   - 表盘数值 / 抄表 → `gauge-reading`
   - 已有结论要成文 → `inspection-report`
   - 多目标混合 → 先 hazard、再 gauge、最后 report
4. **定层级**（详见 `references/escalation-policy.md`）
   Tier 0 高置信直接出结果；临界或需文字描述升 Tier 1；仅"多目标冲突 / 需生成报告"升 Tier 2。
5. **调用子技能并收集结构化结果**；子技能失败 → 降级返回部分结果，同一子技能重试不超过 2 次。
6. **汇总返回** — 每条结论含 `source_skill` / `confidence` / `tier` / `evidence_ref` / `requires_human_review`。
7. **本技能不生成报告** — 报告一律交给 `inspection-report`。

## 输出契约

对上层返回 `{task_id, inputs, routes:[{skill, reason, tier}], findings:[...], partial: bool, disclaimers:[...]}`。
子技能之间的数据契约见 `references/routing-table.md` 的 Schema 段——`inspection-report` 依赖它。

## 负向边界（何时本技能不该被调用）

- 用户已指明"读这个表 / 查这个隐患" → 直接进对应子技能，**不要**过编排层。
- 纯文字问答、写代码、写文档 → 不调用本技能及其任何子技能。
- 只有一句"帮我看下这张图"且图非工业场景 → 先问场景，不要盲跑。
