## 「隔离标识」的真实语义（v1.5 相关，带锚点）

| 事实 | 锚点 |
|---|---|
| 列名是「隔离标识」，页面口径是**生成隔离标识禁止流转**（FR-QM-002） | `index.html:2251` / `:2203` |
| 登记抽屉的字段名是**「隔离标识（数量 / 区域）」**，取值为 `已隔离 · 2,400 · QC 隔离区` / `未隔离` | `index.html:9308` / `:9252` |
| 🔴 **同为物料类的两条种子行取值不同**：`QA-20260813-001` 电机线圈电阻超差 = **未隔离**；`QA-20260813-002` 绕线 PIN 超长 = **已隔离** | `index.html:2256` / `:2260` |
| 关联规则：BR-QM-005「不良立即隔离」、OQC「已隔离禁止发货」、SFC「失败 SN 隔离禁入包装站」 | `:2561` / `:9191` / `:4046` |

⇒ **`iso` 不是「是否涉及物料」，而是「是否实际执行了物料隔离」。** 两条种子行都是物料超差却取值相反，
说明它是**登记时的处置决定**，不是发现类型的属性。

**取值规则 `[团队自定]`**（MES / SRS 无「巡检发现该不该隔离」的规定，此条必然是我们定的）：
现场安全类发现（人员 / 通道 / 渗漏 / 仪表）**不扣留任何物料** ⇒ 一律 `false`。
置 `true` 仅当发现明确涉及在制产品 / 物料批次**且已执行隔离**；当前上游 finding 契约无此信号源，
**不实现分支**（未定义的口径不发明）。

⚠️ **原型行为须知**：`setExcRow`(`:9161`) 会在**任何状态推进**时改写该列（`closed → 已解除`，其余 → `已隔离`），
即 `未隔离` 只在行保持 `found` 时显示。这是原型的状态派生逻辑，非我们的输出，**不规避也不掩饰**。

## 状态口径（我们落的行）
